# Database & ORM Guide

This guide explains our MySQL relational database, SQLAlchemy ORM modeling, relationships, and data integrity rules from zero for beginners.

---

## 1. Relational Database Concepts

| Concept | Simple Meaning | Real-World Analogy | In Our Project |
| :--- | :--- | :--- | :--- |
| **Database** | The entire digital storage container. | A filing cabinet in an IT department. | `cloud_it_portal` on MySQL 8.0. |
| **Table** | A structured grid for storing a specific type of thing. | A folder inside the cabinet (e.g., "Employees" or "Tickets"). | `users` and `service_requests`. |
| **Row (Record)** | A single entry in a table. | One employee's record or one specific ticket. | A user with `id=1, email=john@company.com`. |
| **Column (Field)** | A specific attribute of each record. | The label on a form (e.g., "Full Name" or "Status"). | `title`, `priority`, `role`. |
| **Primary Key (PK)** | A unique identifier for every row that can never duplicate. | A National ID number or Passport number. | `id INT AUTO_INCREMENT PRIMARY KEY`. |
| **Foreign Key (FK)** | A column in one table pointing to the Primary Key of another table. | A badge number written on a ticket showing who filed it. | `service_requests.user_id` pointing to `users.id`. |

## 2. Entity Relationship Diagram (ERD)

```text
+-------------------+             +-----------------------+
|       USERS       |             |   SERVICE_REQUESTS    |
+-------------------+             +-----------------------+
| id (PK)           | 1         * | id (PK)               |
| full_name         |-------------| user_id (FK)          |
| email (Unique)    |             | title                 |
| hashed_password   |             | service_type          |
| role              |             | priority              |
| department        |             | status                |
| created_at        |             | description           |
+-------------------+             | automation_log        |
                                  | created_at            |
                                  | updated_at            |
                                  +-----------------------+
```

### Relational Mapping:
* **One-to-Many Relationship**: One `User` can submit many `ServiceRequests`.
* **Referential Integrity (`ON DELETE CASCADE`)**: If an employee account is deleted, their associated service requests are automatically removed, preventing dangling or orphaned records in the database.

## 3. Database Tables Breakdown

### Table: `users`
* `id` (`INT`, Primary Key, Auto Increment): Unique identifier for the user.
* `full_name` (`VARCHAR(100)`, Not Null): Name of the user.
* `email` (`VARCHAR(150)`, Unique, Indexed, Not Null): Login email address. An index speeds up queries during login.
* `hashed_password` (`VARCHAR(255)`, Not Null): Bcrypt one-way hash string. Plaintext passwords are never stored.
* `role` (`VARCHAR(20)`, Default: `EMPLOYEE`): Access control level (`EMPLOYEE` or `ADMIN`).
* `department` (`VARCHAR(100)`, Nullable): Organizational department (e.g., Engineering, DevOps).
* `created_at` (`DATETIME`, Not Null): Timestamp generated by MySQL server clock (`server_default=func.now()`).

### Table: `service_requests`
* `id` (`INT`, Primary Key, Auto Increment): Unique ticket identifier.
* `user_id` (`INT`, Foreign Key $\rightarrow$ `users.id`, Not Null, Indexed): The owner who submitted the ticket.
* `title` (`VARCHAR(150)`, Not Null): Short summary of the request.
* `service_type` (`VARCHAR(50)`, Not Null): Type of service (`VM_PROVISION`, `S3_ACCESS`, `DB_ACCOUNT`, `PASSWORD_RESET`).
* `priority` (`VARCHAR(20)`, Default: `MEDIUM`): Priority level (`LOW`, `MEDIUM`, `HIGH`).
* `status` (`VARCHAR(20)`, Default: `PENDING`): Ticket state (`PENDING`, `IN_PROGRESS`, `COMPLETED`, `FAILED`).
* `description` (`TEXT`, Nullable): Request details.
* `automation_log` (`TEXT`, Nullable): Timestamped execution transcript generated by the simulated automation engine.
* `created_at` & `updated_at` (`DATETIME`): Audit timestamps automatically maintained by MySQL.

## 4. How SQLAlchemy Talks to MySQL

```text
Python Code:
new_user = User(full_name="John Doe", email="john@co.com", ...)
db.add(new_user)
db.commit()

       ↓ (SQLAlchemy ORM translates Python object to SQL)

SQL Dialect via PyMySQL Driver:
INSERT INTO users (full_name, email, hashed_password, role, created_at)
VALUES ('John Doe', 'john@co.com', '$2b$12$...', 'EMPLOYEE', NOW());

       ↓ (Network TCP Port 3306)

MySQL Server:
- Validates UNIQUE constraint on email
- Assigns next AUTO_INCREMENT id (e.g., 1)
- Writes row to disk storage engine (InnoDB)
```

## 5. What Happens When a Service Request is Created?

1. The client sends a `POST /api/requests` payload containing `title`, `service_type`, `priority`, and `description`.
2. The user's identity is extracted from their verified JWT token (`current_user.id`).
3. SQLAlchemy constructs a `ServiceRequest` object linking `user_id = current_user.id`.
4. SQLAlchemy starts a database transaction.
5. MySQL checks that `users.id` exists (Foreign Key constraint).
6. The record is inserted with `status = 'PENDING'`.
7. `db.commit()` finalizes the transaction.
